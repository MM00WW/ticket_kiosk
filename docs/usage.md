## 使用流程

1. 取号页选择大分类，再勾选一个或多个小分类；可以返回分类继续添加其他需求。确认后连续取得 A001、A002、A003。
2. Window 1 点击 **Go online**，切换 **Automatic allocation**，点击 **Ready to receive**；分配 A001。
3. 广播页显示 A001 → Window 1。首次点击 **Enable voice** 解锁浏览器语音，再选择 EN / 中文 / DE。
4. Window 2 上线，保持 Manual，点击 **Call next ticket** 得到 A002。
5. Window 1 点击 **Start service** → **Complete service**，回到 IDLE；A003 仍在等待。
6. Window 1 再次准备接待，分配 A003。

### 两级需求分类

取号屏提供七个大分类、33 个小分类：电脑与硬件、账号与登录、网络与 VPN、软件与应用、打印与外设、设备领取／归还、其他／不确定。至少选择一个具体问题才能取号；可以跨大分类多选，也可同时选择“其他／不确定”。已选需求持续显示，点击标签的移除按钮可取消；切换分类会保留选择。取号失败保留选择，取号成功后展示号码和需求，点击返回后清空，方便下一位用户使用。

工程师等待队列、当前服务和管理页面显示完整的“大分类 › 小分类”标签。需求仅帮助工程师提前了解问题，FIFO 和手动／自动分配行为保持现有规则。公共广播及语音只播报号码和窗口，不展示需求。

分类代码、父子关系及三语名称集中在 `src/lib/issueCatalog.ts`，图标在取号组件中按目录映射；新增流程文案在 `src/i18n/issues.ts`。默认英文，也支持中文、德语及深浅色模式。分类由代码维护，首版不提供后台编辑、文字输入、工程师修改或按分类分流。

升级现有项目时，先停止服务并备份 `data`，执行 `npm run db:init`、`npm run build` 后重新启动。新增迁移仅给 Ticket 添加 `issues` JSON 字段，历史记录默认为 `[]`，界面显示“未指定”；已有号码、服务状态和日志不会被重置。

窗口初始为 OFFLINE，需要主动上线。AUTO 无号时停留 READY；多窗口 READY 按 `readyAt`，同时间按窗口 ID 排序。切换为 MANUAL 会将 READY 取消为 IDLE；CALLING/BUSY 切换模式不会中断当前服务。

语音使用客户端浏览器 SpeechSynthesis，实际中文/英文/德语声音依赖 Windows/浏览器安装的语音包。重复叫号使用新事件 ID 再次播报；初次打开和重连读取历史记录不会补播所有历史叫号。浏览器不支持语音时给出提示。全屏需点击 Fullscreen；可按 Esc 退出。
